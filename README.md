# Healthcare chatbots: claim–evidence reproducibility

Analytical companion to **From User Experience to Organizational Value: A Critical
Integrative Review of Intelligent Chatbots in Healthcare Services**.

Prepared snapshot version **1.0.0**. This is a **data-and-code-only** repository:
no unpublished manuscript draft, editorial correspondence, author declarations,
patient records, credentials, or copyrighted primary-article PDFs are included.

## Reproduce in one command

Use **Python 3.10 or newer** from the repository root:

```sh
python check_reproduction.py
```

No `pip install`, private package, API key, network connection or trained model is
needed for the analytical check. It verifies the supplied checksums, reruns all
calculations, compares the regenerated outputs with the supplied expected outputs,
runs the tests, and rebuilds the 15-sheet evidence workbook using Python's standard
library. The rebuilt workbook is written to `build/Healthcare_Chatbots_Evidence.xlsx`.
The last line should say **REPRODUCIBILITY CHECK: PASS**. Intermediate logs remain in
`build/` and are not committed.

Individual commands:

```sh
python 03_code/verify_package.py
python 03_code/reproduce.py
python 03_code/build_workbook.py --output build/Healthcare_Chatbots_Evidence.xlsx
python -m unittest discover -s 03_code -p "test_*.py" -v
```

Run the integrity check before changing tracked files. The workbook has cached
formula results and can be opened without special software. The CSVs and code are
authoritative; workbook semantic equivalence, not application-specific rendering,
is the reproducibility target.

## What the analysis reproduces

| Quantity | Expected result |
|---|---:|
| Historical healthcare-specific reports | 22 |
| Historical contextual reports | 4, outside the 22-report denominator |
| Contemporary illustrative reports | 4, not pooled with historical counts |
| Coding/eligibility scenarios | 6 |
| Leave-one-out runs | 22 |
| Outcome co-occurrence pairs | 10 |
| Worked cases | 9 |
| Analyst-specified claim assessments | 18 |
| Claim dispositions | 2 supported, 7 qualified, 7 not established, 2 not assessed |

The historical corpus has 22 user-outcome flags, 11 clinical-outcome flags, one
referral-safety proxy, one health-system operations flag and one patient-productivity
flag. **An outcome flag means it was measured, not that benefit was demonstrated.**

## Files and provenance

- `01_data/`: report identities, extraction, coding, source locators, endpoint
  populations, claim assessments, framework crosswalk, and the evidence workbook.
- `02_methods/`: coding definitions, article title, and bibliographic metadata.
- `03_code/`: dependency-free analysis, tests, workbook writer and integrity checks.
- `04_outputs/`: reference outputs and table source data; numerical outputs are
  regenerated by the one-command check.
- `05_provenance/`: correction records and an explicitly unassessed candidate queue.
- `docs/`: variable dictionary, output-to-code map, verification limits and release guide.
- `.github/workflows/reproducibility.yml`: CI configuration for Windows and Linux,
  with Python 3.10, 3.12 and 3.13. A configured workflow is not proof that the hosted
  checks have run; inspect the repository's Actions tab for actual results.
- `SHA256SUMS.txt`: file-byte integrity manifest. `MANIFEST.json` lists the same files.

The data, analytical algorithms and expected numerical results are preserved from
the corrected data/code archive. Repository-only tests and documentation have been
added; the original combined submission bundle remains the author's local record.

## Evidence boundaries

This is a **non-systematic critical integrative review with a fixed illustrative
corpus**, not an exhaustive literature search, independent re-extraction by two
human reviewers, or validation of the proposed framework. Historical search exports
and paired screening records were unavailable. Source checks have different access
levels. The 53-record candidate queue is not an included-study set or a completed
exclusion log. Hosting these files does not remedy those limitations.
